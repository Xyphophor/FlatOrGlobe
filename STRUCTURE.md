# How this repository is laid out

Every number on the site can be traced from the page to the files it was computed from. This page says where
things are, and how to follow a number back.

## Following a number back

1. On the site, the section that shows it has a **code · data** button: it names the dataset, the code and the
   generated file.
2. The dataset is a directory of `data/` with a `dataset.json` (what the data are, sources, licence, evidence
   class, what result would favour the flat model, the code, the page sections) and an `inputs.lock` (the
   SHA-256 of every input file).
3. Beside every data file, a `<file>.explain` says where it comes from exactly, how it was obtained (downloaded,
   or typed by hand from a scan, and by whom), its checks, what could still be wrong in it, its hash, and why it
   is not in this repository when it is not. Files that the source can give again are checked by
   `tools/bin/fog verify <dataset>`.
4. The dataset's fog target (`tools/internal/build/<package>/`) turns the inputs into a generated file in
   `src/data/presets/`, whose header carries the hash of every input; `go doc -all ./internal/build/<package>`
   (from `tools/`) gives the method with its formulas and references.
5. The page code (`src/tabs/<tab>/`) reads that file and draws the section.

Files that no dataset produces (typed by hand, ported from the old one-file page, computed once by a script,
photographs, maps, portraits) are described in `data/other.json`, and have their `.explain` too.

## Top level

| path | what it holds |
|---|---|
| `index.html`, `vite.config.js`, `package.json` | the site's shell and its build (Vite, plain JavaScript) |
| `src/` | the site: every tab, the shared code, the generated data, the texts in each language |
| `data/` | the raw material and the datasets (`data/README.md` gives the format) |
| `tools/` | `fog`, the data compiler in Go: `data/` → `src/data/` (no network when building) |
| `scripts/` | Node scripts: checks of the site without a browser, the AI-mode pages, the pre-rendered videos |
| `research/` | exploratory scripts (Python), some of which produced files described in `data/other.json` |
| `public/` | files served as they are: photographs, maps, portraits, the AI-mode pages (`ai/`, `llms*.txt`) |
| `raster/` | the Rust/wasm Canvas 2D rasteriser used to pre-render the cards as videos |
| `legacy/` | the original one-file page (`flat-or-globe-2.20.0.html`), kept unchanged as the reference |
| `deploy/` | the container image and its Kubernetes manifests |
| `LICENSE` | MIT for the code, CC BY 4.0 for the content; the exceptions are named there |

## `src/`

| path | what it holds |
|---|---|
| `src/main.js` | the tab bar, the lazy mounting of tabs, navigation, the code · data buttons |
| `src/tabs/<tab>/` | one directory per tab: `index.js` (mount, render, teardown), `logic.js` (pure computations, with `logic.test.js`), figures, animations, `exp.js` (its experiments, shown in the falsify tab), `style.css` |
| `src/core/` | shared code: map projections, ephemerides, figures, TeX to MathML, translations, citations, evidence badges, provenance |
| `src/data/presets/` | the generated data files (and a few typed by hand), each with its `.explain` |
| `src/data/prose/` | the text of the tabs that come from the original page, as blocks |
| `src/data/sources/` | each tab's numbered sources |
| `src/data/cards/` | the export cards of each tab |
| `src/data/dem/` | horizon profiles of the photographs' viewpoints, from terrain models |
| `src/data/provenance.js`, `src/data/datasets.js` | the datasets as the page sees them (written by fog) |
| `src/i18n/<lang>/` | the translations (English is the source; French complete; Spanish, Portuguese, Dutch partly) |

## `data/`

One directory per dataset, for example `data/sun/romer/`:

| file | what it is |
|---|---|
| `dataset.json` | the manifest (format in `data/README.md`) |
| `inputs.lock` | SHA-256 of every input, `sha256sum -c inputs.lock` checks it without fog |
| `inputs.norm` | when present: the hashes without the lines that change at every download (a dated header) |
| `raw/` | files as downloaded; large ones or ones that may not be republished are not in git, their `.explain` is |
| `transcription/` | tables we typed from scans, one file per page or table, checked by the build |
| `<file>.explain` | the description of each file (generated by `fog build explain`) |

`data/other.json` describes the files compiled from no dataset; `data/elev/` holds the original photographs.

## `tools/` (fog)

| command | what it does |
|---|---|
| `fog build <target> \| all` | compile `data/` into `src/data/` (`--check`: fail if a file is stale) |
| `fog fetch <dataset>` | download the missing inputs (the only command that uses the network to fill `data/`) |
| `fog verify <dataset>` | download again into a temporary directory and compare with the lock |
| `fog validate`, `fog lock`, `fog list`, `fog audit` | check the manifests, write a lock, list the targets, static audits |

`make ci` runs the whole local check: Go tests, `fog validate`, `fog build --check all`, the unit tests, the
mount of every tab, the AI-mode pages, the video fingerprints.

The working notes of the project (journal, task tracker, open questions) are kept outside this repository.
